# ADR 0003：会话认证、SQLite 运维契约与定时任务

- 状态：已接受
- 日期：2026-11-24
- 决策者：项目负责人
- 相关：ADR 0002、`docs/review/gpt-review-v1.0.md`、`docs/需求基线-v1.2.md` §10.2

## 背景

ADR 0002 定稿时给出的是技术栈与范围，未细化到认证形式、SQLite 运行参数、迁移与任务调度。开工前评审（`docs/review/gpt-review-v1.0.md`）指出四处会在首个切片就返工的问题：JWT 会话、SQLite 锁与备份、迁移工具、定时任务实现。本 ADR 定稿这四项，其余仍按 ADR 0002。

## 决策

### 1. 认证：服务端会话，不用 JWT

- 登录成功后在 `member_session` 插入一行，Cookie 只放随机会话 ID（`Secure`、`HttpOnly`、`SameSite=Lax`）。
- 数据库存会话 ID 的 SHA-256 摘要与过期时间，不存原文。
- 8 小时过期；登录换新 ID；改密、退会、除名、管理员强制下线均撤销该会员全部会话。
- 所有写操作校验 CSRF token（表单隐藏字段或同源 `Origin` 校验，二选一，实现时取表单字段，覆盖面更稳）。

理由：单体 SSR 应用用 JWT 时，撤销要靠黑名单或短过期+刷新，等于自己实现一遍会话表还多出前端存储风险。会话表能直接表达“这个设备被踢了”。

### 2. SQLite：WAL + busy_timeout + 统一引擎工厂

- `PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000`、`PRAGMA foreign_keys=ON` 在**每个物理连接**上设置，由统一引擎工厂注入，Web、CLI、迁移、测试共用。
- CSV 导入、OJ 拉取等耗时操作放在事务外；解析校验完成后按 100 行一批短事务写入，按业务键幂等重跑，返回已提交批次数。
- 写锁超时返回 503 并提示可重试，不吞掉错误。
- **复核触发**：短事务下仍持续出现锁超时，或写入 p95 超过 1 秒，改用 PostgreSQL（ADR 0002 复核条件）。

### 3. 迁移：显式 SQLite 迁移脚本，不用原样 MySQL DDL

`docs/数据库设计-v1.0.md` 的 DDL 是逻辑模型基准，其中 `UNIQUE KEY`、`KEY`、`ENGINE=` 等 MySQL 子句不能直接在 SQLite 执行。落地方式：

- 用 Alembic 管理版本（`alembic upgrade head` 空库与上一版各跑一次），模型用 SQLAlchemy 2.0 显式声明约束。
- 索引与唯一键按 SQLite 语法书写（`CREATE UNIQUE INDEX ... ON ...`）。
- 不做“把 MySQL DDL 机械替换字符串”的生成方式。

### 4. 定时任务：systemd timer 触发一次性 CLI

- 宿主机 `*.timer` 配 `Persistent=true`，触发 `docker compose run --rm cli <job>`。
- 每次运行在 `job_run` 表落一行（业务日、状态、摘要），漏跑按日期补扫；同一业务日唯一键控制重跑。
- 不用 APScheduler（与 Web 进程生命周期耦合），也不直接写 crontab（错过时间不补跑）。

### 5. 备份：SQLite Online Backup API

- `make backup` 用 Online Backup API 生成一致快照，连同附件清单一并打包，写入校验和与迁移版本。
- `make restore-check` 在隔离卷恢复，跑 `integrity_check` 与 `foreign_key_check`，抽验登录、导出与附件读取。

## 后果

- 接口设计需移除 `/auth/refresh`，改为会话 Cookie；新增 CSRF 校验说明。
- 数据库设计新增 `member_session`、`attachment`、`member_application`、`task_assignee`、`checkin_problem`、`job_run`、`oj_account`、`oj_submission` 八张一期表。
- 一期范围仍是 A+B 23 项，但表从 19 张增至 27 张。
