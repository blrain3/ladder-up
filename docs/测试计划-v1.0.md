## 1. 测试范围

| 阶段 | 功能范围 | 执行与证据 |
|---|---|---|
| 一期 | A 会员与协会、B 题库与训练，共 23 项 | 全量执行矩阵并提交结果，验收入会、转正、训练、档案导出与备份恢复 |
| 二期前段 | C 集训、D 赛事，共 24 项 | 启用时细化寒暑假、赛事类型和异常分支。队伍先用固定 E 域夹具，待 E 上线后跨域复验 |
| 二期后段 | E 组队 7 项 | 启用时复验能力评估、标准队、报名及赛站分配链路 |
| 三期可选智能服务 | F 域 5 项，基线第 5 节列为二期候选 | 按训练历史和独立范围审批启动，另建测试基线 |

需求基线第 2 节的 A–E 共 54 项作为覆盖全集。工程期次沿用设计说明书第 10 节，先交付 A+B，二期先 C+D 后 E，三期考虑 F。基线第 5 节补记的导出、备份、审计与权限进入对应阶段验收。跨域数据通过受控夹具模拟，A+B 验收保留真实的会员、题库和训练数据读写。

## 2. 测试策略

| 层级 | 对象与判定 | 主责与执行时点 | 工具建议 |
|---|---|---|---|
| 单元 | 状态迁移、计算、过滤、权限策略、截止时间，比较确定输入和输出 | 开发，提交前及每次 PR | 随技术栈选 pytest、JUnit 或 Vitest，注入时钟与规则配置 |
| 接口 | 请求契约、授权、错误响应、持久化副作用 | 开发编写，测试评审，PR 回归 | HTTP 客户端与测试框架、OpenAPI 校验 |
| 集成 | Docker 数据库、迁移、存储、异步任务、跨域写入与回滚 | 测试与开发共同维护，合并及候选版本触发 | Docker Compose 或 Testcontainers、可重放 HTTP stub、数据库查询 |
| 验收 | 按业务角色完成工作流，以界面、导出和日志核验结果 | 业务代表确认，测试准备数据并记录 | 浏览器或 Playwright、导出文件核对、验收记录 |

用例结果记录构建标识、配置版本、范围、执行时间、预期与实际、证据位置及缺陷编号。结果状态为待执行、通过、失败、阻塞或本阶段不适用。断言优先核验持久化事实和业务状态，界面提示与 HTTP 响应同时留证。

## 4. 关键场景

除另述外，每条用例从独立数据快照开始，使用经评审的角色与规则。涉及尚未确认的阈值和排序采用第 7 节夹具参数，作为测试输入保存。

| 场景 | 前置与执行步骤 | 判定与留证 |
|---|---|---|
| S01 入会全流程（一期） | 准备三名独立申请人和有权限的审核员。① 申请人提交完整报名表，审核通过，录入通过面试，发送录取通知与会员证。② 另一人资格审核不通过。③ 第三人审核通过、面试不通过。另以已存在学号尝试提交以覆盖前置校验。 | 成功申请按待审核、待面试、观察会员推进，通知、会员证与同一学号对应。两个业务失败分支均可追溯拒绝原因，均无发证及观察会员权限。重复学号拒绝且无第二份有效申请。保存申请历史和通知记录。 |
| S02 观察期转正（一期） | 准备已学期注册的观察会员 M01、M02。① 下发入门任务，两人分别提交达标与未达标的训练、考核数据。② 运行考核任务并公示，按配置执行转正。③ 重跑同批任务，刷新两人权限。 | 达标者转为正式会员并得到授权，未达标者保留观察身份。公示结果与考核快照相符，重跑只保留一份有效结果与转正记录。保存状态、授权与审计。 |
| S03 退会与除名（一期） | 准备两名有训练历史的正式会员。① M03 提交退会，先以无权账号审批，再由授权者批准。② M04 由授权者记录违规事由并执行除名。③ 两人使用原会话重访问会员写接口，再由管理员查看历史。 | 未授权审批无副作用，批准后分别为已退会与已除名。会员写权限失效，训练与档案可由授权角色查询，除名事由、操作者与时间可查。 |
| S04 奖惩与综测（一期） | 为 M03 创建一条奖励与一条惩处，奖励关联夹具分值 2，惩处留事由。① 以授权角色登记。② 用无权账号尝试修改分值。③ 查询与导出档案。 | 记录的类型、事由、综测分值与所属会员正确。导出能核对奖励的关联值，未授权修改失败且原值保持，登记与变更有审计证据。 |

### 题库与训练

| 场景 | 前置与执行步骤 | 判定与留证 |
|---|---|---|
| S05 题目录入与检索（一期） | 准备树形知识点及 Q01–Q04，四题在难度、来源或题型上形成对照。① 录入完整题面及输入输出样例。② 构造缺样例请求按字段契约校验。③ 分别用单项和组合条件筛选，再查询无匹配条件。 | 完整题目字段与关联回读一致，非法输入无残留。组合条件仅命中预期题目，结果为空时返回可辨识的空列表。保存请求、预期题号与实际题号。 |
| S06 训练任务下发与打卡（一期） | 建学期计划及基础、强化、冲刺阶段。① 将 Q01、Q02 组包，通过 `task_assignee` 定向下发给 M01、M03。② M01 截止前打卡并逐题填报完成情况，M02 访问同一任务应 403/404。③ M03 漏卡触发提醒后补卡。 | `task_assignee` 只含 M01、M03；`checkin_problem` 逐题记录与实际一致；非指派会员访问被拒；同一 `(member, task, date)` 重复打卡返回 40901 且不产生第二行。 |
| S07 OJ 同步幂等（一期） | Codeforces 用 HTTP 回放（录制的公开 API 响应），Vjudge 用两次相同 CSV 导入。① 记录首轮计数与 `job_run` 状态。② 重放同一批。③ 注入一次 429 后恢复。④ 再注入连续 429 耗尽重试。 | 两次导入后 `oj_submission` 行数不变，提交挂到正确会员与题目；分支③ `status=success`、分支④ `status=failed` 且 `detail` 有最后错误；限流期间训练打卡不受影响。 |
| S08 进度落后预警（一期） | 发布包含 4 个计数单位的任务，分别构造完成 1、2、4 项及未被分配的会员。配置低于 50% 预警。① 冻结时钟到巡检窗口。② 执行、重跑巡检。③ 落后会员补齐数据后执行下一轮。 | 只有 25% 的会员初次触发，50% 达临界值，未分配者按无任务处理。单次窗口无重复有效预警，补齐后当前状态按规则恢复。保存分子、分母及通知。 |

## 8. 缺陷管理

| 级别 | 定义与示例 | 处置 |
|---|---|---|
| S1 致命 | 数据不可恢复、跨角色敏感数据泄露、系统不可用 | 立即分诊，停止相关发布，修复及回归通过后关闭 |
| S2 严重 | 入会、训练关键流程阻断，状态或成绩错误，无可接受的绕行方式 | 纳入当前阶段修复，验收前关闭 |
| S3 一般 | 局部功能异常且存在可行绕行 | 排入迭代，延期需评审 |
| S4 轻微 | 文案、排版或其他轻微可用性问题 | 记录影响并按优先级处理 |

流转为新建 → 分诊 → 已指派 → 修复待复验 → 已关闭。复验失败则重开，重复、延期和无法复现均需留理由。单据包含关联 FR、用例、构建号、环境、复现数据、预期、实际、影响及证据。测试负责复验，开发提交修复证据，交付负责人确认延期及验收影响。
