## 2. 设计目标与约束

本章将基线 §9 的部署、数据、时间与集成约束落实到系统边界。

| 约束 | 设计落实 |
|---|---|
| 校内单机、单应用实例、Docker | 同一台服务器部署应用和本地关系库。只开放 Web 入口，数据库走内部网络。 |
| 百人级会员，无高并发要求 | 以分页、索引和短事务支撑日常工作。以报名截止、批量下发和归档导出作为峰值验收场景。 |
| 附件持久化及每年一次全量备份 | 照片和附件优先用本机挂载目录，落库保存归属、权限和校验信息。年度备份覆盖业务库及归档所需文件。 |
| Asia/Shanghai 及按日任务 | 每日按上海业务日期计算考勤与预警。时刻保存为可还原的统一时间，学期、学年及业务日使用明确的本地日期口径。 |
| 外部服务有配额及可用性限制 | GitHub、Codeforces、Vjudge 通过适配器接入，按平台限流。训练打卡、任务下发和本地数据查询独立于远端同步。 |

单一会员身份贯穿训练、集训、队伍、赛事与归档。业务验收以能够从统计结果追溯到原始记录、规则版本与关键操作为目标。A–E 共 54 个功能点构成基线实施范围，F 的 5 项智能服务属于后续范围，见基线 §2、§4、§5.3。

## 3. 总体架构

本章定义六层职责、依赖方向及六个业务域在架构中的位置。

### 3.1 分层与依赖

| 层 | 职责 | 依赖方向 |
|---|---|---|
| 接入层 | Web 页面与 HTTP API，处理会话、请求格式、分页参数、错误响应与文件流 | 接入层 → 应用层 |
| 应用层 | 编排用例，执行权限检查、事务、跨域调用与审计写入 | 应用层 → 领域层及各域公开接口，经端口使用数据和外部能力 |
| 领域层 | 持有业务实体、值对象、状态迁移规则和数据访问契约 | 领域规则依赖本域模型和小范围共享类型 |
| 数据层 | 实现持久化契约，负责数据库映射、查询索引、迁移与附件元数据 | 数据层 → 领域或应用端口，同时依赖数据库与文件系统 |
| 集成层 | 适配 OJ、GitHub 及后续身份源，转换外部标识与错误 | 集成层 → 应用端口，同时依赖外部平台 |
| 运行保障层 | 装配运行环境、触发作业、检查健康、采集日志、执行备份 | 调度入口 → 应用任务接口，备份工具 → 持久化资源 |

各域业务写入由拥有数据的模块校验并提交。跨域传递本地标识、必要字段和快照版本。底层实现由运行配置装配。数据库事务覆盖状态迁移及其必要的业务记录，网络调用和文件流传输位于事务外。学期、学年和外部账号绑定等共同语义通过有归属的模块接口查询。

### 3.2 六域与图 1-1 的对应

| 域 | 数据输入与输出 |
|---|---|
| A 会员与协会 | 提供会员、部门、状态和归属的只读查询。训练、参赛数据以源域发布结果汇入档案。A 的档案应用服务编排查询，B 的会员查询依赖 A 的主数据接口，两者独立于对方的档案编排。 |
| B 题库与训练 | 只读引用 A。向 C 提供发布版本的题目包，向 E 提供训练记录和测评汇总。 |
| C 集训 | 使用 B 的题目包，经 E 的建队接口完成集训队伍分配。集训表现以已确认汇总提供给资格确定用例，见基线 §4.4。 |
| D 赛事 | 接收 E 提供的队伍报名输入，维护报名、名额、赛站和成绩。按队伍标识提供已发布战绩，供队伍档案展示。 |

图 1-1 的箭头兼有引用和数据流含义。E → D 表示队伍报名进入赛事，同时由 D 返回报名状态及已发布成绩。C → E 表示集训组队协作。A 汇总训练与成绩及 D 读取集训表现是需求补充的数据查询，分别见基线 §4.1、§4.4。各域共用分层结构，运行保障层为各域提供统一作业、审计和备份能力。

## 5. 技术选型

本章用统一尺度比较候选技术栈，给出适合单机交付的建议。

本节为建议，最终由 ADR 0002 定稿。评分采用 1～5 分，分数越高表示越适合本项目，四项等权。团队实际技术熟悉度待调查，该列暂统一给中性分 3。部署成本按容器、升级与备份负担评估，生态按认证、迁移、测试和报表配套评估，扩展按事务写入及模块演进评估。评分是设计判断。

| 方案 | 团队熟悉度 | 部署成本 | 生态 | 后续扩展 | 合计 |
|---|---:|---:|---:|---:|---:|
| Spring Boot + MySQL | 3 | 3 | 5 | 5 | 16 |
| FastAPI + PostgreSQL | 3 | 4 | 5 | 5 | 17 |
| Node.js + SQLite | 3 | 5 | 4 | 3 | 15 |

推荐 FastAPI + PostgreSQL。按 Python 应用与数据库两个核心组件估算交付成本，Python 可同时承载 Web API、数据整理和报表作业，PostgreSQL 可用唯一约束、行锁和事务支持报名名额、成绩更正和归档。Spring Boot + MySQL 适用于团队已有 Java 实战及维护经验的情形，具备完整的模块化实现路径。Node.js + SQLite 减少常驻数据库进程，批量导入、同步和审批并发写入时需验证写锁竞争及备份流程。ADR 0002 应记录团队熟悉度调查和登录、迁移、定时任务、备份恢复的试做结果，并据此复核评分。

## 6. 关键设计决策

本章记录影响业务一致性、维护成本和数据恢复的主要取舍。

| 问题 | 方案 | 备选与放弃理由 |
|---|---|---|
| 1. 单体还是微服务 | 采用模块化单体。应用单实例按域分包，以公开应用接口约束内部调用。定时执行复用同一应用及用例代码。 | 微服务增加服务发现、网络故障处理、部署及跨服务事务成本，当前数据量与单机约束下收益有限。 |
| 2. 单库还是分库 | 使用一个关系数据库，表及迁移按域归属管理。通过外键、唯一约束和事务维护会员引用、报名及名额一致性，读接口封装跨域访问。 | 按域分库会增加身份引用、事务协调、恢复和年度导出的复杂度。 |
| 3. 定时任务如何运行 | 在单应用进程内启用轻量调度器。任务按业务日持久化运行记录，启动和周期巡检识别漏跑日期，可从失败批次续跑。以任务名、日期及必要的业务对象去重，重跑复用应用校验。 | 宿主机 cron 需额外部署脚本和环境注入。独立消息代理及任务集群对当前作业量增加常驻组件和排障成本。 |
| 4. 外部 OJ 拉取还是推送 | 按平台及账号限流拉取。绑定后发起异步同步，定时补拉。按平台及提交标识去重，标识仅账号内唯一时加入账号键。分页写入与游标推进同事务提交，拉取小范围重叠以兼顾延迟到达。 | 推送取决于上游回调能力及校内入站条件。同步请求与打卡同事务会把远端限流传导给用户。 |
| 5. 文件与照片怎样存储 | 挂载私有本地目录。数据库保存对象键、归属、类型、大小及哈希。临时写入后原子改名，再提交元数据，按保留窗口清理孤儿文件。下载经资源权限校验。 | 数据库保存大文件会扩大数据库备份与恢复负担。校内对象存储待确认服务与凭据。外链难以保证可访问性和归档可恢复性。 |
| 6. RBAC 还是简单角色判断 | 采用角色绑定权限点、授权范围绑定资源的 RBAC。操作同时校验角色、资源归属、业务状态和字段可见性。 | 在各控制器直接判断角色容易遗漏资源范围，也难处理成员、队长、命题等职责叠加。 |
| 7. 审计日志如何落库 | 关键业务变更和审计行在同一事务写入追加表，记录操作者、对象、动作、差异摘要、时间和请求标识。失败鉴权另记安全日志。 | 仅写文本日志难以证明业务提交与审计一致。独立审计服务增加双写失败场景和运行依赖。 |
| 8. 学年归档如何锁定 | 按学年记录归档状态及版本。预导出绑定数据版本，复核确认时事务内锁定学年控制记录并校验版本。所有涉及该学年的写入及作业共用此控制记录。锁定后补正经授权生成关联更正记录和新归档版本，保留原导出。 | 仅在前端隐藏按钮会遗漏批处理和接口写入。整库只读会阻塞新学年。覆盖原归档使已交付材料无法复核。 |

OJ 达到限额或收到退避提示时暂停该平台的批次，在限速预算内重试。页面展示最近成功时间及待同步状态。题目导入保留来源链接及映射键，自动同步补充证据时保留人工打卡与补卡历史。接口或授权不可用时保留手工登记路径，见基线 §9、§10。

年度导出期间允许正常办理事务，数据有更新时重新生成待确认包。锁定覆盖该学年的档案快照、考核、奖惩、训练、集训、报名和成绩等历史记录。跨学年引用继续指向可追溯的快照，会员当前联系方式可以更新。备份失败时保留锁定版本，标记待备份并重试，校验通过后记录归档完成。

## 8. 非功能设计

本章给出性能验收口径、可用性、数据恢复、日志与安全措施。

| 项 | 建议与验证方式 |
|---|---|
| 负载和响应 | 并发 20 个活跃会话（估算值）。在拟部署单机、百人级会员及覆盖完整学年的构造数据下，常用分页查询 p95 ≤ 500 毫秒，普通表单写入 p95 ≤ 1 秒（均为目标值，待实测）。分开记录本地请求、外部同步和文件导出耗时。 |
| 查询与批处理 | 对会员标识、学年、任务截止、赛事报名状态及考勤日期建立适用索引。归档导出、外部同步走受限后台批次，提供进度和失败原因。用峰值报名叠加一次日任务检查响应及名额一致性。 |
| 可用性 | 单机故障期间服务中断。应用与数据库配置自动重启和健康检查。适配器超时时返回最近成功同步的本地状态，发现同步滞后与日任务漏跑时记录告警。 |
| 数据备份 | 每年至少一次全量备份，见基线 §9。建议日常每日逻辑备份及升级前备份。清单包含数据库导出、照片附件、归档导出包、版本与校验和。通过暂停文件删除及固定附件清单保持数据库与文件可配对，另存加密的异机副本，存放位置须符合学校数据要求。 |
| 恢复验证 | 计划恢复点不超过 24 小时，恢复时间不超过 4 小时（均为目标值，待实测，以日备份及异机副本可用为前提）。在隔离环境恢复库和文件，核验校验和、外键、附件抽样及归档版本，确认业务日期后恢复调度。 |
| 日志与审计 | 运行日志记录请求标识、错误、作业时间与结果。审计表记录入退会、权限变动、成绩更正、资格、赛站及归档操作，按角色授权访问。保留期由校方评审确认，日志与归档副本独立管理。 |
| 凭据与隐私 | 凭据以受限挂载文件注入，分别配置应用与备份数据库账号。限制密钥读取和轮换权限。日志、预览、默认导出屏蔽口令、令牌和未授权个人字段。 |
| 越权及内容防护 | 接入启用 HTTPS，服务端验证会话、来源与请求参数。渲染题解时清理不安全 HTML，上传校验内容类型和大小，文件键由服务端生成。以跨部门、跨队伍、越权审批及绕过归档锁作为验收用例。 |

## 9. 部署架构

本章规定单机 Docker Compose 的组件、网络关系、持久化目录和作业入口。

以下部署以第 5 章推荐方案为示例。校内客户端经 HTTPS 访问反向代理，代理经前端网络访问应用，应用通过后端网络连接数据库。数据库仅加入后端网络，应用通过允许的出口访问指定外部接口。部署时先执行数据库迁移，应用在数据库及迁移检查通过后接收流量。

| 组件 | 网络和入口 | 目录及卷 |
|---|---|---|
| proxy | 宿主机发布 HTTPS 端口，经前端网络转发 Web 与 API 请求 | 代理配置和 TLS 证书只读挂载 |
| app | 前端网络接收代理请求，后端网络访问数据库，按配置访问外部平台 | `./data/uploads:/srv/app/uploads`、`./data/exports:/srv/app/exports`，配置及秘密文件只读挂载 |
| db | 后端网络接收应用和备份连接 | `db-data` 命名卷挂载到数据库数据目录 |
| backup | Compose 一次性作业，连接后端网络读取逻辑备份所需数据 | 上传与导出目录只读挂载，`./backups:/backup` 可写，核验后复制到异机 |

相对路径基于部署目录，持久化目录限制为相应容器账号可访问。常规进程由建议命令 `docker compose up -d` 启动，生产配置仅启用一个应用调度实例。调度器读取 Asia/Shanghai 业务日，依次执行应到日判定、考核计算、打卡提醒、进度与考勤预警，并触发受限 OJ 同步。补跑入口与常规作业共用作业记录及幂等键。归档确认后生成备份待办，值班人员通过建议入口 `docker compose run --rm backup` 处理待办并保存校验结果。目录、服务名和运行命令为部署设计，随 ADR 0002 对应实现确定。
