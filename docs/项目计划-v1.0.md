## 1. 计划依据与执行口径

需求基线第 2 节的 A–E 54 项用于全量设计与测试追踪；第 10.10 项已定稿为“一期交付 A+B 共 23 项可运行系统”，其余 31 项本期只交设计与图。排期按真实日期：2026-11-24 至 2026-12-18，共 4 周（最后一周仅 4 天）。

执行模式是**单人 + AI 编码代理**：本人负责写规格、审 diff、跑验证，不逐行手写代码。因此工作量不以“人日 × 人数”计量，见第 5 节的切片口径。

## 3. 四周里程碑

每周退出条件是**可执行的命令或页面**，不是“完成开发”。证据保存在对应提交与 CI 记录里。

| 里程碑 | 日期 | 可验收产物 | 退出条件（命令级） |
|---|---|---|---|
| M1 骨架、认证与入会 | 11/24–11/30 | 上述骨架 + 入会申请、审核、面试、录取 | `make smoke` 从空卷走完启动→迁移→种子→登录；`/health` 返回 200；匿名提交入会申请成功、重复学号 40901；管理账号录取后会员状态为观察会员；观察会员访问他人详情 403；`pytest -q` 全绿 |
| M2 题库与训练起步 | 12/01–12/07 | 题库与知识点、组合检索、题解与统计；训练计划/阶段/任务下发与打卡 | 管理端录两道题并按知识点+难度检索命中；任务下发给指定会员后，被指派者能打卡、未指派者 403；`pytest -k problem` 与 `-k training` 全绿 |
| M3 训练闭环与恢复首验 | 12/08–12/14 | 打卡含逐题、进度与预警、周测录分、考核与转正、档案导出；**首次备份恢复演练** | 管理端选两题下发给指定会员，会员端打卡后进度更新，未分配会员看不到该任务；`pytest -k 'training or onboarding'` 覆盖重复提交与截止边界；考核任务连跑两次只生成一条记录 |
| M4 交付 | 12/15–12/18 | 冻结标签、23 项结果矩阵、部署与恢复说明、演示录屏 | 干净环境执行 `make smoke`、`pytest -q`、`make backup` + `make restore-check` 全部通过；用未分配账号复验权限；同一构建录制演示 |

| 检查时点 | 检查动作 | 失败后的处理 |
|---|---|---|
| 每日 | 看当日切片是否跑通 `make smoke` 与相关 `pytest` | 未通过不进下一切片，先修或缩范围 |
| 周末 | 复现该周退出条件，记录证据位置 | 缺口写入下周首日，按第 7 节的砍范围顺序处理 |
| 12/15 | 冻结候选标签，不再加功能 | 只修阻塞缺陷；剩余功能改为已知问题 |

## 4. 开发线路：纵向切片

**按纵向切片推进，不按横向分层。** 每个切片一次交付：迁移 + 模型 + 业务服务 + 页面 + 接口 + 测试 + 种子数据。理由是横向分层（先建全部表、再写全部接口、最后做前端）会在前三周没有任何可演示的东西，而课程验收和自查都依赖“能跑起来的页面”。

| 切片 | 优先级 | 内容（FR 编号） | 建设表 |
|---|---|---|---|
| S1 骨架 | P0 | 环境、迁移、会话登录、角色与权限（A-01、A-02） | `member`、`department`、`permission_point`、`member_permission`、`member_session`、`sys_config`、`audit_log` |
| S2 入会 | P0 | 申请、审核、面试、录取、会员证（A-03） | `member_application`、`attachment` |
| S3 题库 | P0 | 知识点、录题、题型与难度、组合检索（B-01、B-02、B-03、B-04） | `knowledge_point`、`problem`、`problem_kp` |
| S4 训练 | P0 | 计划、阶段、任务、定向下发、打卡与逐题、进度（B-07～B-11） | `training_plan`、`training_phase`、`training_task`、`task_problem`、`task_assignee`、`checkin`、`checkin_problem` |
| S5 考核转正 | P0 | 周测录分、考核计算、转正审批、退会除名（B-12、B-13、A-04、A-05） | `assessment_test`、`test_score`、`member_assessment`、`job_run` |
| S6 档案与扩展 | P1 | 档案 CSV、统计、题解、题量统计、奖惩（A-06、A-07、A-08、B-05、B-06） | 复用（`member_award`、`problem_solution`） |
| S7 OJ 同步 | P2 | Codeforces 拉取 + Vjudge CSV 导入、规则建议（B-14、B-15） | `oj_account`、`oj_submission` |

依赖关系：S1 → S2 → S3 → S4 → S5 是硬链，后一个切片依赖前一个的业务键与页面骨架；S6、S7 可在 S5 之前插入，也可在最后补。

**砍范围顺序**（截止前 3 天仍未完成时按此执行，砍任何一项都需本人签核并同步第 8 节放行口径）：S7 → S6 的 Excel/PDF 双格式与富交互图表 → B-14 规则建议 → S6 整体。砍掉的项在 README 与验收矩阵里标为“未实现”，不写成已完成。

### 最小可演示闭环

报名 → 管理员审核面试并录取 → 下发定向题包 → 观察会员登录、打卡、看进度 → 管理员录周测、跑考核、审批转正 → 导出含训练与考核的会员档案。用未分配账号验证越权被拒，用审计日志串起同一学号的操作。演示全部使用本地种子数据，不依赖现场网络。

### 表建设顺序

一期 27 张表按切片逐次建立，不做“一次性建完 38 张”。C/D/E 的 11 张表本期只保留设计与图，代码里不出现。

## 5. 工作量估算

估算不用“人日 × 人数”，改用**切片数 × 单切片 AI 轮次 × 人工审核时间**。原因是代码由代理生成，瓶颈在审阅与验证，不在打字。

| 项 | 估算 | 依据 |
|---|---|---|
| 切片数 | 7（S1–S7） | 见第 4 节 |
| 单切片 AI 编码轮次 | 1–3 轮 | 首轮出可用实现，次轮修评审意见；S1 与 S4 偏多 |
| 单切片人工审核 | 1.5–3 小时 | 读 diff、跑测试、手点页面 |
| 一期总人工投入 | 约 30–40 小时 | 7 切片 × (2 轮 + 2 小时审核) + 交付周 6 小时 |
| 每周可用容量 | 12–15 小时 | 非全职，按每周 5 个晚上 + 周末半天 |

原 68 人日（约 540 小时）的口径作废：那是四人全时排产，与单人非全职的实际不符。按上表，4 周容量 48–60 小时，与 30–40 小时的估算之间留了约 50% 缓冲，缓冲用于返工与演示准备。

| 周 | 切片目标 | 人工小时预算 | 风险 |
|---|---|---:|---|
| 11/24–11/30 | S1 + S2 | 10–12 | SQLite 三处 PRAGMA 与迁移链首次跑通；附件表与会员表同批迁移 |
| 12/01–12/07 | S2 收尾 + S3 + S4 | 10–12 | 任务定向与打卡唯一键的组合 |
| 12/08–12/14 | S4 完成 + S5 + S6 + S7 | 12–14 | 考核计算与转正状态机；SQLite 写锁与 OJ 限流 |
| 12/15–12/18 | 交付与演示 | 6–8 | 二次恢复演练、录屏与签核 |

**若实际用工超出预算 30%**：按第 4 节的砍范围顺序削减，不延长工期——课程截止日期不可移动。

## 7. 风险登记

概率和影响采用高、中、低三级，为定性估算。高影响表示可能阻断一期退出或引入严重数据问题，中影响表示局部返工或验收延期，低影响表示可在当前迭代内吸收。

| 编号 | 风险及触发信号 | 概率 | 影响 | 应对及责任 |
|---|---|---|---|---|
| R01 | OJ 限流、接口变化或平台授权未落实，出现持续失败 | 高 | 高 | 开发负责人先做契约样本与连接验证，落地重试、幂等与任务隔离。无法合规联通时提请调整排期或范围 |
| R02 | 身份方案或附件后端晚定，模型和部署反复变更 | 中 | 高 | 开工前签核方案，用角色烟测与可恢复样例验证设计，技术取舍记 ADR |
| R03 | 考核、综测口径反复，计算与导出不一致 | 中 | 高 | 业务代表签核实例与规则版本，测试固定边界数据，规则变化进入评审 |
| R04 | 跨域标识和状态不同步，离会账号仍可训练或旧记录丢失 | 中 | 高 | 开发负责人统一会员标识与授权判断，测试复验离会、重试和历史可读 |
| R05 | Excel 字段不一致或出现重复学号，迁移脏数据 | 中 | 高 | 迁移纳入时先试导入脱敏样表，输出冲突清单，由业务确认映射，保留可恢复副本 |
| R06 | 四周可用容量低于估算，独立回归被挤压 | 中 | 高 | 交付负责人每周检查容量和依赖，启用预留并调整排期，锁定迭代验收窗口 |
| R07 | 数据库备份可恢复而附件缺失，导致档案不完整 | 中 | 高 | 开发负责人覆盖附件及配置引用，M4 前由测试在空实例恢复并核对文档和附件 |
