## 3. 九项"部分实现"的降级点

| 编号 | 需求原文要求 | 实际实现 | 原因与影响 |
|---|---|---|---|
| FR-A-02 | 管理会员细分会长 / 副会长 / 部长 / 副部长 | `role` 四类（member / dept_admin / coach / sys_admin）+ 授权表 | 细分到职务会让权限矩阵膨胀，且课程场景没有对应审批链；需要细分时在 `permission_point` 增加条目即可，不改表结构 |
| FR-A-03 | 录取通知（邮件/短信） | 录取结果页显示一次性密码，人工转达 | 课程环境没有可用 SMTP 与收件人；接口层预留 `notice` 字段，接通知只加一个适配器 |
| FR-A-05 | 考核结果公示 | 结果在 `/promotions` 与管理页可见，未做面向全体的公示页 | 公示涉及隐私边界（谁能看谁的成绩）未定，先只给本人与管理者 |
| FR-A-07 | 档案含竞赛成绩 | 赛事节保留表头并标注「赛事模块随 D 域交付」 | 赛事表在 C/D 域，本期只交设计与图（基线 §10.10） |
| FR-A-08 | 生成报表 | 统计页可视化 + 组合维度，未做报表导出 | 需要先定报表口径（按学期/按届），不在本期范围 |
| FR-B-04 | 难度评审流程 | 六档难度可设、可筛，未做评审流转 | 评审流程本质是审批链，与 C/D 域的赛事流程同构，留待二期 |
| FR-B-05 | 代码高亮 | Markdown 渲染（代码块保留原样文本），无语法高亮 | 高亮需引入前端库，与「禁 CDN、零构建」的约定冲突；纯文本可读 |
| FR-B-06 | 正确率 | 字段已输出，当前恒为 `null` 并显示「暂无数据」 | 正确率依赖 OJ 提交数据；S7 只同步 Codeforces，样本不足时不做假数 |
| FR-B-12 | 能力曲线 | 存 `kp_snapshot` 快照，未画曲线 | 曲线需要多次测评的连续数据，课程周期内只有 1–2 次测评，画出来是假象 |
| FR-B-14 | 基于能力评估生成个人计划 | 三条固定规则建议（连续缺卡 / 完成率 / 知识点偏低），每条带数值依据 | 生成"计划"需要推荐算法与足够样本，先给可解释的规则建议，不编造个性化 |
| FR-B-15 | OJ 题目导入 | 提交记录同步（CF 拉取 + Vjudge CSV），未做按 OJ 题号批量建题 | 题目导入需人工确认题意与难度，自动建题会产生大量脏数据；现有手工录题 + `problem` 的 `platform/external_id` 字段已为将来留好键 |

> 注：用例数按测试文件归属统计，同一用例可服务多项 FR，故列合计（347）大于全量用例数（291）。§3 共 11 行、对应 11 项「部分实现」；FR-A-03 与 FR-B-15 各含两个降级点，合并在同一行内。

## 6. 复现方式

```bash
make migrate && make seed              # 空库建到 head（0009）并灌种子（角色/部门/权限/演示账号）
make lint && make cov                  # ruff + 覆盖率门槛 80%
pytest -q --junit-xml=/tmp/junit.xml   # 全量 291 项，用于复核本矩阵的用例数
make smoke                             # 17 个环节的端到端（离线），内部自建临时库与业务样例
python scripts/probe_s2.py             # 各切片对抗探测：probe_s2 ~ probe_s7、probe_ui
```

业务样例数据没有单独的 `make demo-seed` 目标——`make smoke` 会在临时库里造题库、任务、打卡等样例，演示环境需要时可照 `scripts/smoke.sh` 的构造顺序手工执行。此处如实说明，不写成已存在的命令。
