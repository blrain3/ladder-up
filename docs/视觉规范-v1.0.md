# 视觉规范 v1.0

- 日期：2026-11-25
- 适用范围：全部服务端渲染页面（`app/templates/` 38 个模板）
- 技术基线：Bootstrap 5.3.3（本地托管）+ Bootstrap Icons，无前端构建、无 CDN、无 JS 框架
- 本文是**唯一视觉依据**：新增页面与改版必须先对照本文，不一致即视为缺陷

## 1. 设计原则

| 原则 | 含义 | 具体表现 |
|---|---|---|
| 一致优先 | 相同语义的元素在任何页面长得一样 | 标题层级、卡片、表格、按钮位置全站统一 |
| 克制动效 | 只做状态反馈，不做装饰 | 过渡时长 ≤ 150 ms；不引入滚动动画、视差 |
| 信息密度 | 管理后台以数据为主 | 表格行高紧凑（`table-sm` 由页面按需），不滥用留白 |
| 可读性 | 中文正文优先 | 正文 16 px / 行高 1.6；表格 14 px |
| 零依赖 | 不引入 CDN 与构建链 | 新样式只加到 `app/static/app.css`，总量控制在 5 KB 内 |

## 2. 设计令牌

所有取值来自 Bootstrap 的 CSS 变量，页面**不得**硬编码颜色与圆角。

| 令牌 | 取值 | 用途 |
|---|---|---|
| 间距阶梯 | `0.25 / 0.5 / 0.75 / 1 / 1.5 / 2 / 3 rem` | 只允许用这些值（对应 BS 的 `1..5`），禁止 `padding: 13px` 这类随手值 |
| 圆角 | `var(--bs-border-radius)`（0.375rem）/ 卡片用 `var(--bs-border-radius-lg)` | 卡片、输入框、按钮 |
| 阴影 | `shadow-sm`（唯一允许的层级） | 卡片仅表单页与统计卡使用 |
| 字体 | 系统栈（不引入 Web Font） | 中文优先，`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif` 由 Bootstrap 提供 |
| 字号阶梯 | h1 `1.75rem` / h2 `1.375rem` / h3 `1.125rem` / 正文 `1rem` / 辅助 `0.875rem` | 一级页面标题固定 h1，卡片内小标题 h2/h3 |
| 语义色 | primary 主操作 / success 通过·在册 / warning 待处理 / danger 危险·失败 / secondary 中性·已归档 | 与 `status_badge` 宏一一对应，禁止另造颜色 |
| 容器宽度 | 全站 `container`（最大 1320 px）；表单页 `col-lg-4/5`；表格页占满 12 列 | 表单永远居中，数据页永远占满 |

## 3. 页面骨架

每个页面必须由这三段构成，顺序固定：

```
[页头]     h1 标题 + 一行说明（可选）+ 右侧主操作按钮（可选）
[反馈区]   alert（由 base.html 统一渲染，页面不要自己做）
[内容区]   下列四类之一
```

### 3.1 页头

```html
<div class="d-flex flex-wrap justify-content-between align-items-center gap-2 mb-3">
  <div>
    <h1 class="h3 mb-1">会员列表</h1>
    <p class="text-muted small mb-0">共 5 位会员</p>
  </div>
  <div class="d-flex gap-2"><!-- 主操作按钮 --></div>
</div>
```

规则：
- 每页**有且仅有一个** `<h1>`，用 `h1.h3`（视觉大小与层级解耦，保证大纲正确）
- 说明文字一律 `text-muted small`
- 主操作在右，次操作在左或下拉，不超过 3 个按钮

### 3.2 内容区四种形态

| 形态 | 结构 | 适用 |
|---|---|---|
| 表格页 | `div.table-responsive > table.table.table-hover.align-middle` | 列表、审批、统计明细 |
| 表单页 | `row.justify-content-center > col-12.col-sm-10.col-md-8.col-lg-5 > .card.shadow-sm > .card-body.p-4` | 登录、申请、改密、录分 |
| 详情页 | `row.g-3`：左侧主信息 `col-lg-8`，右侧元信息 `col-lg-4`（`.card` 承载） | 会员详情、题目详情、任务详情 |
| 统计页 | `row.g-3` + 若干 `col-6 col-md-3 > .card > .card-body`，数字用 `h2.mb-0` | 档案统计、题目统计 |

### 3.3 空状态

列表为空时**不显示空表格**，改用：

```html
<div class="text-center text-muted py-5">
  <i class="bi bi-inbox fs-1 d-block mb-2" aria-hidden="true"></i>
  暂无数据
</div>
```

### 3.4 错误页（`error.html`）

- 居中，`col-lg-5` 卡片
- 结构：图标（`bi-exclamation-triangle`，`fs-1 text-danger`）+ 一句话说明 + 错误码（`text-muted small`）+ 返回入口按钮
- 返回入口按场景：401 → `/login`；403 → 上一页或 `/members`；404 → `/members`

## 4. 组件规范

### 4.1 表格

- 必须包在 `.table-responsive`（窄屏可横向滚动，不许截断）
- 统一 `.table.table-hover.align-middle`；表头不加 `table-dark`，保持默认浅色
- 状态列一律用 `status_badge` 宏，不手写 `<span class="badge">`
- 数字列右对齐（`text-end`），操作列放最后且右对齐
- 行内不放超过 2 个操作；3 个及以上收进 `btn-group` 或详情页

### 4.2 按钮

| 层级 | 类 | 用在哪 |
|---|---|---|
| 主操作 | `btn btn-primary` | 每屏最多 1 个（提交、保存、下发） |
| 次操作 | `btn btn-outline-secondary` | 取消、返回、导出 |
| 危险操作 | `btn btn-outline-danger` + `data-confirm="确定…？"` | 删除、除名、作废、退会 |
| 行内小操作 | `btn btn-sm` | 表格操作列 |

- 图标按钮必须有可访问名称（图标加 `aria-hidden="true"`，按钮保留文字）
- 危险操作**必须**带 `data-confirm`，由 `app.js` 统一拦截；这是 E2E 断言项

### 4.3 表单

- 每个控件：`label.form-label[for]` + `input.form-control`（或 `.form-select`），`<label>` 与 `id` 必须对应
- 必填项在 label 后加 `<span class="text-danger" aria-hidden="true">*</span>`，并在 `<input>` 上加 `required`
- 校验错误：`input.is-invalid` + 紧随其后的 `<div class="invalid-feedback">原因</div>`
- 控件间距 `mb-3`；提交按钮与上方控件间距 `mt-4`
- 手机端（<576px）表单占满宽度、左右各 16px 内边距，不允许横向滚动

### 4.4 提示与徽章

- 全局提示（成功/失败）只由 `base.html` 的 alert 区渲染，页面内不要再写 alert
- 行内说明用 `text-muted small`，不要用灰色小卡片模拟
- 徽章只通过 `status_badge` 宏产出；新增状态必须同时扩展宏，不得页面内临时拼类名

### 4.5 卡片与统计块

- 只有表单页、详情页右栏、统计页数字块使用 `.card`；列表页**不用**卡片包裹整张表
- 卡片内边距统一 `p-4`（表单）/ `p-3`（统计块）
- 不叠加多层阴影或描边

## 5. 响应式

| 断点 | 行为 |
|---|---|
| ≥1200px | 表格完整展示；表单 `col-lg-4/5` 居中 |
| 768–1199px | 表单 `col-md-8`；导航仍展开 |
| 576–767px | 表单 `col-sm-10`；表格横向滚动；导航折叠成汉堡菜单 |
| <576px | 全部单列；表单占满；按钮可 `w-100` 堆叠；不允许出现横向滚动条 |

导航折叠是 E2E 断言项：窄屏下 `.navbar-toggler` 可见，点击后 `#main-nav` 展开。

## 6. 可访问性

- 每页一个 `<h1>`，标题层级不跳级
- 所有 `input` 有 `label`；所有图标 `aria-hidden="true"`；装饰性元素不进无障碍树
- 焦点可见：不覆盖 `:focus-visible` 的默认轮廓
- 对比度：正文与背景 ≥ 4.5:1（Bootstrap 默认色板已满足，禁止自造浅灰文字）
- 弹窗类交互（`data-confirm`）用原生 `confirm`，保证键盘可用

## 7. 打印

会员证 `member_card` 是唯一打印场景：

- `@media print` 下隐藏 `.no-print`、`.navbar`、`footer`
- 白底、无边框、A4 单页内呈现
- 见 `app.css` 现有规则，改版不得破坏

## 8. 禁止事项

| 禁止 | 原因 |
|---|---|
| 引入 CDN 资源、Web Font | 内网/离线环境不可用 |
| 内联 `<style>` 块、行内 `style=` | 无法统一审计，探针无法校验 |
| 新增 JS 框架、构建链 | 与"零构建"约定冲突 |
| 硬编码颜色十六进制值 | 主题改不了，深浅不一致 |
| 自造徽章/按钮类名 | 与 `status_badge` 宏重复 |
| 动效 >150 ms、滚动动画 | 干扰阅读 |

## 9. 工程化落地（可执行验收）

规范不靠自觉，靠脚本。新增 `scripts/probe_style.py`，对**每个页面**断言：

| 编号 | 断言 | 判据 |
|---|---|---|
| ST-01 | 每页有且仅有一个 `<h1>` | 正则计数 |
| ST-02 | 列表页表格包在 `.table-responsive` 内 | 有 `<table` 的页面必须出现 `table-responsive` |
| ST-03 | 表单页用居中卡片 | 有 `<form` 且非行内操作表单的页面，必须出现 `justify-content-center` 与 `card` |
| ST-04 | 无内联样式块与 `style=` 属性 | 全量扫描 |
| ST-05 | 无 CDN 引用（`http://`、`https://` 出现在 `src`/`href`） | 全量扫描 |
| ST-06 | 危险操作按钮带 `data-confirm` | 含「删除/除名/作废/退会」字样的按钮 |
| ST-07 | 所有图标带 `aria-hidden="true"` | 扫描 `class="bi bi-` 元素 |
| ST-08 | 输入控件都有 `label[for]` 对应 | 解析 `<input`/`<select` 的 `id` 与 `<label for>` |
| ST-09 | 样式文件总大小 ≤ 8 KB（`app.css`） | 文件字节数 |
| ST-10 | 空列表渲染空状态而非空表格 | 需构造空库访问关键列表页 |

落地要求：
- `make style` 运行该探针；挂进 `make check`（顺序 lint → typecheck → test → style → smoke）
- CI 的 `quality` job 增加 Style 步骤
- 首版必须 10 项全绿；后续任何页面改动导致红，即视为回归
