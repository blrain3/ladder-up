## 2. 通用约定

**风格**：REST，资源用复数名词，动作用子资源表达（`POST /members/{id}/approve`），不用动词型路径。

**基础路径**：`/api/v1`。版本号进路径，不做请求头协商。

**认证**：服务端会话。登录成功返回 `Set-Cookie: sid=<随机 ID>; Path=/; HttpOnly; Secure; SameSite=Lax`（`Secure` 默认仅在 `APP_ENV=production` 启用，可用 `COOKIE_SECURE` 覆盖），服务端在 `member_session` 存该 ID 的 SHA-256 与过期时间，有效期 8 小时。不使用 JWT，不提供刷新端点：过期即重新登录，登录时换发新 ID。`POST /auth/logout` 撤销当前会话行并返回 204 + 清 Cookie；退会、除名、强制下线撤销该会员**全部**会话；改密撤销其余会话并把当前会话轮换为新 ID（先撤销再签发，不沿用旧 ID）。见 ADR 0003。

**CSRF**：除 `POST /auth/login`（无会话、无敏感副作用，且 `SameSite=Lax` 已挡住跨站提交）与 `POST /member-applications`（匿名，走双提交）外，**所有** POST/PUT/DELETE 都校验令牌。载体按客户端类型三选一，不叠加：

| 场景 | 载体 | 说明 |
|---|---|---|
| 已登录 HTML 表单 | 隐藏字段 `csrf_token` | 服务端渲染时注入 |
| 已登录 JSON 请求 | 请求头 `X-CSRF-Token` | 与表单同一令牌，不做双份实现 |
| 匿名表单（入会申请） | 双提交 Cookie | 页面下发 `csrf_anon` Cookie（`SameSite=Lax`，不绑定会话），提交时隐藏字段必须与其一致；不校验会话 |

匿名申请的令牌签发：`GET /apply` 由服务端生成随机值，写入 `csrf_anon` Cookie（`Path=/`、`SameSite=Lax`、不绑定会话）并渲染进隐藏字段；提交地址同为 `POST /apply`，两者相等才通过。不提供匿名 JSON 提交入口。

失败处理：已登录提交缺令牌或不等 → 40002 并撤销当前会话（防反复试探）；匿名提交不等 → 40002，只返回错误，无会话可撤销；`csrf_anon` 过期或缺失 → 重新打开 `/apply` 取新令牌。

**权限**：每个接口声明所需权限点（如 `member:approve`），中间件按 `member_permission` 校验；越权返回 403。

**分页**：查询参数 `page`（从 1 开始）、`size`（默认 20，最大 100），响应含 `total`、`page`、`size`、`items`。

**时间**：请求与响应均为 `yyyy-MM-dd HH:mm:ss`，Asia/Shanghai。日期用 `yyyy-MM-dd`。

**统一响应**：

```json
{ "code": 0, "message": "ok", "data": { } }
```

错误时 `code` 非 0，`data` 为 `null` 或错误详情：

```json
{ "code": 40001, "message": "学号已存在", "data": { "field": "studentNo" } }
```

**重复提交**：不提供通用幂等请求头。重复提交由业务唯一键拦截——打卡以 `(member, task, date)`、成绩以 `(test, member)`、报名以 `(contest, team)` 为准，冲突返回 40901 并带已有记录 id。批量导入按业务键 upsert，返回新增/更新/跳过三类计数。

## 3. 错误码

| code | HTTP | 含义 | 典型场景 |
|---|---|---|---|
| 0 | 200 | 成功 | |
| 40001 | 400 | 参数校验失败 | 必填缺失、格式错误 |
| 40002 | 400 | 业务规则拒绝 | 状态不允许该操作 |
| 40101 | 401 | 未登录或 token 过期 | |
| 40301 | 403 | 无权限 | 越权访问、审批人为自己 |
| 40401 | 404 | 资源不存在 | |
| 40901 | 409 | 唯一键冲突 | 学号重复、同一赛事重复报名 |
| 40902 | 409 | 并发冲突 | 名额已满、队伍已解散 |
| 42901 | 429 | 触发限流 | 外部 OJ 同步、批量导出 |
| 50301 | 503 | 数据库写锁超时 | 批量导入与打卡并发，`busy_timeout` 到期；响应带 `Retry-After: 1` |
| 50001 | 500 | 服务内部错误 | |
| 50002 | 502 | 外部依赖失败 | 外部 OJ / 邮件服务不可用 |

## 5. 关键接口示例

**入会申请（匿名，表单 + 双提交令牌）**

```http
POST /apply
Content-Type: application/x-www-form-urlencoded
Cookie: csrf_anon=<token>

csrf_token=<token>&studentNo=202400000000&name=张三&major=软件工程&grade=2024&phone=138****0000&email=zhangsan@example.com
```

提交成功直接返回 SSR 结果页，显示申请编号和查询回执码。后续在 `/apply/status` 输入回执码查询。缺 `csrf_token` 或与 Cookie 不等返回 40002，页面内提示重新提交。

同一学号**存在活跃申请**（`active_flag=1`）时返回 `40901`，表单页内提示“该学号已有申请在处理中”；历史终态申请不阻止新申请。录取接口为 `POST /member-applications/{id}/admit`，成功后置 `已通过`、回填 `member_id`，并在同一事务内创建会员。录取成功直接返回 HTML 结果页，一次性密码仅在该页显示一次，首次登录后必须改密。已有会员须按其状态另行处理。

**打卡（幂等）**

```http
POST /api/v1/checkins
{ "taskId": 88, "minutes": 90, "solvedCount": 1,
  "problems": [ { "problemId": 101, "solved": true, "attempts": 2 },
                { "problemId": 102, "solved": false, "attempts": 3 } ] }
```

同一 `(member, task, date)` 重复提交返回 `40901`，`data.existingCheckinId` 指向已有记录；`problems` 覆盖式写入 `checkin_problem`。`solvedCount` 必须等于明细中 `solved=true` 的条数，服务端以此校验并在进度统计中只认明细，不认这个数。

**资格确定（批量 + 事务）**

```http
POST /api/v1/contests/12/qualify
{ "teamIds": [3, 7, 9], "rule": "按预选赛名次前 60% 且集训出勤率 ≥ 80%" }
```

响应返回每支队伍的判定结果（`qualified` 布尔 + `reason` 文本），整体在一个事务内提交；任一队伍资格冲突（如已报名其他赛站占满名额）返回 `40902` 并整体回滚。

**赛站分配（名额校验）**

```http
POST /api/v1/contests/12/site-allocation
{ "allocations": [ { "teamId": 3, "siteId": 5 }, { "teamId": 7, "siteId": 5 } ] }
```

赛站名额不足返回 `40902`，`data.conflicts = [{ "siteId": 5, "quota": 10, "requested": 11 }]`。

## 6. 与外部系统的集成

| 外部 | 方式 | 约束 |
|---|---|---|
| Codeforces | REST 拉取用户提交（`user.status`），按 `(platform, externalId)` 幂等写入 `oj_submission` | 1 请求/2 秒，失败重试 3 次后跳过并记入 `job_run.detail` |
| Vjudge | 无公开 API，管理员导出 CSV 后导入 | 按 `(platform, externalId)` 去重，导入返回新增/更新/跳过计数 |
| GitHub | **不做**。课程环境无真实仓库可抓，且需 token 授权 | — |
| 邮件（可选） | SMTP | 通知类，失败不阻塞主流程 |
| 支付 | 一期不对接 | 报名费只记金额与备注 |

同步类接口一律异步：返回 `jobRunId`，前端轮询 `/oj/sync-tasks/{id}`。同一 `job_name + 业务日` 只允许一行 `job_run`（唯一键），重复触发不新建行，改为在 `detail` 里记 `attempts=n` 并在上一次仍为 `running` 时返回 40902（“已有实例在运行”）。

## 7. 对应决策

已由需求基线 v1.1 第 10 节与 ADR 0002 定稿，接口设计按下列结论落地：

| 事项 | 结论 | 对接口的影响 |
|---|---|---|
| 统一身份认证 | 不对接校内 SSO | 只实现自建账号 + 服务端会话；保留 `POST /auth/sso` 路径占位，未实现时返回 501 |
| 报名费支付 | 一期不对接支付 | `/contests/{id}/signups` 只记 `fee` 与 `feeNote`，无回调接口 |
| 附件存储 | 本地磁盘 + 统一出口 | `/files` 读写本地卷，签名 URL 不做；权限在 `GET /files/{id}` 内校验 |
| 移动端扫码签到 | 二期可选 | 一期只有网页签到；二维码接口留待二期，不预留空实现 |

遗留项仅一条：若二期接入扫码签到，需新增 `POST /camps/{id}/attendance/qr` 与一次性 token 校验，不改动现有打卡接口。
