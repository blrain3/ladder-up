# 拾阶开工前技术评审 v1.0

**结论：保留 Python 3.11、FastAPI、SQLite 和 Jinja2/Bootstrap 5，修订认证、迁移、备份和交付线路后开工。** 原计划按 68 人日、第三周四人全时排产，单人非全职加 AI 无法照搬。11 月 24 日至 12 月 18 日保留 A+B 23 项为验收范围，先跑通主线，再以简版补齐边缘功能。AI 按切片提交，人负责定规格、审 diff、跑验证。以下阈值和排期均为建议，未运行应用或测量性能。

## 一、技术选型

| 方案 | 在单人、24 天、3.8 GB 单机上的判断 |
|---|---|
| FastAPI + SQLite | **当前首选。** 可沿用 REST 契约和 Python 的 CSV、任务与测试工具链。一个应用镜像加本地数据卷，教师可复建。需自行实现会话、表单 CSRF 和对象授权，首周先验证。 |
| FastAPI + PostgreSQL | 保留 API 和 Python 代码，多写者与行锁更适合导入高峰。增加数据库服务、凭据、迁移与恢复演练。低配机可运行，当前演示负载缺少换库依据。 |
| Spring Boot + MySQL | Security、事务和测试集成成熟。需重做 Web、数据访问和交付入口，并维护 JVM 与 MySQL。除非已有可直接复用的工程和熟练经验，否则工期收益不足。 |
| Django + SQLite | 内置认证、会话、CSRF、迁移和后台，若从零做管理表单，可比 FastAPI 省工。任务下发、会员视图和状态审批仍需定制，SQLite 写锁照旧。改选要重接 API、模型和测试入口；现有设计路线下保留 FastAPI。参见 [Django 认证文档](https://docs.djangoproject.com/en/4.2/topics/auth/default/)。 |

**SQLite 可用，写锁和备份风险被低估。** ADR 的“毫秒级”只能视为预期。按基线约 300 人和设计说明书 20 活跃会话的目标，验数据库实盘和业务写入重叠。

| 风险 | 开工前落实 |
|---|---|
| 导入与打卡争锁 | 本地卷启用 WAL，连接设置 `busy_timeout=5000`。CSV 解析、校验及 OJ 网络请求放在事务外；预检后按短批写入，初始每批 100 行，按业务键重跑并报告已提交批次。超时返回可重试的 503。用独立连接让导入和打卡重叠，核对无丢单、重单及部分业务提交。短事务仍持续出现锁超时或写入 p95 超过设计目标 1 秒时，复核 PostgreSQL。参见 [SQLite WAL](https://www.sqlite.org/wal.html)。 |
| 外键 PRAGMA 漏配 | 统一引擎工厂，每个物理连接在事务前设 `foreign_keys=ON`，CLI、测试、迁移接同一初始化。用两个独立连接各验证孤儿插入失败。涉及 Alembic 重建的迁移停写执行，若临时关闭外键，结束后重新开启并运行 `foreign_key_check`。参见 [SQLite PRAGMA](https://www.sqlite.org/pragma.html)、[Alembic 批处理](https://alembic.sqlalchemy.org/en/latest/batch.html)。 |
| 备份与迁移 | 每日及升级前用 SQLite Online Backup API 生成一致库快照，按该快照的附件清单打包，期间冻结文件回收，附迁移版本与校验和并留异机副本。恢复到独立卷，跑 `integrity_check`、`foreign_key_check`，抽验附件、登录和导出。换 PostgreSQL 时重验类型、约束、导数与 ID 序列，再切流。参见 [SQLite WAL](https://www.sqlite.org/wal.html)。 |

| 子系统 | 决策及理由 |
|---|---|
| 前端 | **SSR 优于 Vue/React 分离。** 页面/API 共用业务服务，避免两套校验、构建和登录状态。固定导航、响应式表格、统一表单和状态提示，用进度条与一张测评折线完成演示，少量原生 JS 补交互。Bootstrap 静态资源随镜像发布。 |
| ORM/迁移 | **同步 SQLAlchemy 2.0 + Alembic。** ORM 显式表达关联、复合约束和事务，Pydantic 独立定义请求。SQLModel 节省部分样板，复杂约束仍需 SQLAlchemy；手写 SQL 可用于报表，全面手写会增加模型与迁移同步工作。迁移按切片审查，空库及上一版各执行一次 `alembic upgrade head`。综测分存整数百分位，避免 SQLite NUMERIC 隐式转换。 |
| 认证 | **自建账号与 bcrypt 保留，JWT 改 SQLite 服务端会话。** 随机会话 ID 写入 Secure、HttpOnly、SameSite=Lax Cookie，数据库存摘要和 8 小时过期时间，登录换 ID，退出、改密及退会撤销会话。写表单校验 CSRF；每次请求复查状态、权限及数据范围。JWT 用于此场景仍需撤销机制，刷新与 SSR 存储多一层。同步修订基线 §10.2、接口 §2/§4.1，移除刷新端点。 |
| 测试 | **pytest + httpx/TestClient 足够做主回归。** 每测试用临时 SQLite 文件跑真实迁移，保持 WAL 与多连接语义；纯规则测试无需库，内存库只用于可丢弃的单连接测试。补独立连接竞争测试、受控 OJ 回放和一次真实浏览器双角色走查。参见 [FastAPI 测试文档](https://fastapi.tiangolo.com/tutorial/testing/)。 |
| 定时 | **选 systemd timer。** 宿主机以 `Persistent=true` 定时触发 Compose 一次性 CLI，按上海业务日记录运行并补扫漏日；唯一键控制重跑，线上和手工补跑共用入口。cron 需另做错过时间恢复和日志整合；APScheduler 会耦合 Web 进程重启与 worker 数。 |

主栈无需更换。开工前调整会话、迁移与部署契约的成本集中在首个切片，值得现在改。其余基线决策保留：分页上限 100、私有附件、Codeforces API 与 Vjudge CSV、综测 CSV、历史会员 CSV；网页签到、赛站名额、最终赛果及成绩导入留给 C/D，课程期提供相应设计。

## 二、开发线路

**按纵向切片推进。** 每个切片一起提交迁移、业务服务、页面、必要接口、测试与种子数据。I2 原排 11 项，I3 又堆入训练、测评、转正和 OJ，且 M4 到相对第四周末才演练恢复。改为第 2 周跑通真实训练，第 3 周前移恢复，最后三天用于回归交付。优先级指实施顺序，23 项通过仍是完成门槛。

| 顺序 | 优先级 | 功能与依赖 |
|---|---|---|
| 1 | P0 | A-01、A-02，先固定会员 ID、登录、角色和数据范围，照片随后补齐；A-03 跑报名、审核、面试、站内录取和可打印会员证。 |
| 2 | P0 | B-01、02、04、03，先建知识点及固定难度、录题，再接组合检索；难度评审复用授权与审计。 |
| 3 | P0 | B-07、08、09、10、11，计划与阶段先于发任务，冻结题目及指定会员名单，打卡后按明细计算进度。提醒和补卡复用同一任务。 |
| 4 | P0 | B-12、13 → A-05，再接转正；成绩和训练提供考核输入。A-04 验退会、除名、原会话撤销及历史保留。 |
| 5 | P1 | A-06 → A-07、08，CSV 档案与单页统计；B-05 清洗后的 Markdown 与高亮；B-06 从发题和提交明细聚合，零提交显示空值。 |
| 6 | P2 | B-14 用最近记录和固定规则；B-15 首周先做契约探针，第三周交有限批 Codeforces 拉取和 Vjudge CSV，验重放、限流及失败后手工训练。延期先砍 PDF/Excel 双格式、富交互大屏和历史全量补拉；若仍不足，只能签核延期 B-14 或 B-15 并同步矩阵，按实际通过数报告。 |

**一期复用原清单 18 张，补正文漏列的 1 张，另新增 8 张，共 27 张应用表。** Alembic 版本表另计。按切片逐次建表。

| 处置 | 表清单 |
|---|---|
| 一期 19 张已有 DDL | `member, department, member_assessment, member_award, permission_point, member_permission, knowledge_point, problem, problem_kp, problem_solution, training_plan, training_phase, training_task, task_problem, checkin, assessment_test, test_score, audit_log, sys_config` |
| 一期补 8 张 | `member_session, member_application, attachment, task_assignee, checkin_problem, job_run, oj_account, oj_submission`。申请表统一承载入退会申请，作业表共用来存日任务与 OJ 作业状态。权限配置用代码角色映射和现有授权表。打卡改用业务唯一键处理重复，移除通用 24 小时请求头承诺。 |
| 后置 11 张 | `camp, camp_member, camp_attendance, multi_school_contest, contest, contest_signup, contest_site, contest_result, team, team_member, team_rank`。一期档案经查询接口返回空赛事历史或受控夹具，样本 CSV 验读，无需生产赛事表。 |

下列 `make` 目标为拟新增入口。每周退出证据保存到对应提交。

| 周期 | 可验证的退出条件 |
|---|---|
| 11/24–11/30 | `make smoke` 从空卷执行 Compose 启动、迁移、种子及认证烟测；`/api/v1/health` 返回健康，管理账号看到会员列表，观察会员看本人页且读取他人被拒；CI 留记录。 |

**最小演示闭环**：申请人报名，管理员审核面试并录取，发布定向题包；观察会员登录、打卡、查看进度；管理员录周测、运行考核并审批转正，最后导出含训练和考核的会员档案。用未分配账号验证权限，用审计串起同一学号。演示用本地种子数据，现场无需等待 OJ。

## 三、文档一致性抽查

七份文档已逐份审读。基线 §6 的 20 项是核心实体；测试计划 §3 的 54 个编号与基线 §4.1–4.5 对应。具体分歧如下。

| 文件与章节 | 问题及修订 |
|---|---|
| 需求基线 §2/§10.10/§11；项目计划 §1/§6 | 基线把 54 项称为“本期实现”，实际交付定为 23 项；计划 §1 仍假设可改成只交文档，§6 已关闭。改为“54 项设计追踪、23 项课程实现”，删已过时的假设。 |
| 数据库设计 §3/§4.2/§4.3/§9；ADR 0002 决策一 | 清单 28 张，DDL 多出 `problem_kp` 和 `camp_member`；清单审计估 20 万行，ADR 与 §9 却把 3 万行打卡称最大表。改清单与容量口径。 |
| 数据库设计 §4.0/§9；设计说明书 §5/§8/§9；ADR 0002 决策一 | MySQL `UNIQUE KEY`、`KEY` 不能原样执行；部署仍有网络 db 服务、独立数据库账号及 dump 命令。改用显式 SQLite 迁移、挂载数据库目录与快照恢复。 |
| 需求基线 §10.2/§10.3；接口设计 §4.1/§4.2/§4.7；数据库设计 §4.1/§4.6 | 登录无密码哈希及 `auth_provider` 字段；照片路径无法承载通用附件 ID；申请审批也缺能保存面试与拒绝的实体。补字段及会话、附件、申请三类迁移。 |
