# 拾阶第五轮放行核对 v1.4

仅核对 v1.3 五项条款，未执行验收命令。

## 五项冲突判定

| 核对项 | 判定 | 证据 |
|---|---|---|
| 1. 匿名申请、会话与会员授权 | 未消除 | 接口 §2 与 §5 已统一隐藏令牌表单，Cookie 路径为 `/`。但 §2 写“提交地址同为 `POST /apply`”，§4.2 仍列“`POST /member-applications` 提交入会申请（公开入口，不需登录）”，双提交例外仍指向后一地址。改密方面，§2 写“改密……撤销该会员全部会话”，§4.1 写“撤销该会员除当前外的全部会话，当前会话换发新 ID 并重设 Cookie”，对应先撤销再重建或直接轮换。详情已允许 `member:read:self`，与数据库 §8 的默认授权一致，但 §4.2 列表说明“普通会员调用只返回本人”，权限列仍要求 `member:read`，默认角色会被拒绝。 |
| 2. 代理 80 端口用途 | 消除 | 设计 §9 指定 443 转发业务、80 仅做 301 跳转到 443。路线 S1 检查 443 健康入口及 80 的 301 状态。 |
| 3. 逐题验收与双平台排期 | 消除 | 计划 §3 将逐题完成明细列入截至 12/07 的 M2，路线 S4 同期验收打卡写入逐题明细。M3 明列 OJ 两平台各自通过，计划 §8 分别指定 Codeforces 拉取与 Vjudge CSV 导入。 |
| 4. 签核裁剪后的放行门槛 | 未消除 | 未裁剪时均要求 23 项通过。裁剪后，计划 §8 写“按矩阵实际通过数放行，未通过项列入已知问题并注明原因”，测试 §6 写“按签核清单逐项标‘通过 / 未实现（签核）’”。若一个保留项未通过，前者可读为登记原因后放行，后者只为已签核裁剪项提供未实现标记。 |
| 5. 恢复验证的阶段与命令 | 未消除 | 设计 §8 写“档案导出在 S6 交付后补一次导出抽样”，与路线 S5 首验、S6 补验及 M4 回归的时点一致。但 v1.3 指出的 ADR 0003 §5 仍写“`make restore-check` 在隔离卷恢复……抽验登录、导出与附件读取”。按这句实现，S5 首跑命令就会验导出，按设计 §8 执行则到 S6 才验。 |

## 放行结论

**不可开工。** 匿名入口与会话授权、裁剪门槛、恢复首验仍有执行分歧。
