- 版本：v1.0

- 依据：`docs/项目计划-v1.0.md` 第 4 节、`docs/review/gpt-review-v1.4.md`（开工前五轮评审的末轮放行结论，前四轮见 git 历史）、ADR 0002/0003

本文是执行清单：每个切片列出要交付的文件、验收命令与完成定义，供编码代理按切片实现、由本人审 diff 与跑验证。设计与排期的理由不在这里重复。

## 0. 工程约束

| 项 | 约定 |
|---|---|
| 语言与框架 | Python 3.11、FastAPI、Jinja2、Bootstrap 5（CSS/JS 随镜像发布，不引 CDN） |
| 数据层 | SQLAlchemy 2.0 同步 Session + Alembic；`PRAGMA foreign_keys=ON`、`journal_mode=WAL`、`busy_timeout=5000` 由统一引擎工厂注入 |
| 时区 | 全部 Asia/Shanghai；数据库存本地时间字符串，代码里显式 `ZoneInfo` |
| 认证 | 服务端会话（`member_session` + HttpOnly Cookie + CSRF），不用 JWT |
| 测试 | pytest + FastAPI `TestClient`；每个测试用临时文件库跑真实迁移 |
| 提交 | 一切片一分支一 PR；提交信息见 `docs/工程规范.md` 第 4 节 |
| 日志 | 结构化 JSON 写 `logs/app.log`，含 `request_id`、`member_id`、`path`、`status`、`ms` |

**禁止事项**（违反即打回）：伪造测试通过输出；用 `try/except: pass` 吞异常；把密码、token 写进代码或日志；跳过迁移直接改表；在 Web 进程里起后台线程做定时任务。

## 1. 切片清单

### S1 骨架与认证（P0，11/24–11/27）✅ 已完成

交付：

- `app/main.py`、`app/config.py`（读环境变量，缺项启动即失败）
- `app/db.py`：引擎工厂 + 三个 PRAGMA + `get_session` 依赖
- `app/models/`：`member`、`department`、`permission_point`、`member_permission`、`member_session`、`sys_config`、`audit_log`、**`attachment`**（`member.photo_attachment_id` 引用它，必须与会员同批迁移，不能留到 S2）
- `alembic/`：初始迁移，`upgrade head` 从空库可跑
- `app/auth.py`：bcrypt 校验、会话签发与撤销、`login_required` 与 `require_permission` 依赖、CSRF 校验
- 页面：`/login`、`/members`（列表，分页）、`/members/{id}`（详情）
- `bin/seed.py`：部门、权限点、4 个角色、1 个管理员、4 个会员样例（`make seed`）
- `bin/demo_seed.py`：题库、任务、打卡的业务样例（`make demo-seed`，S3 之后才可用）
- `Makefile`：`smoke`、`seed`、`demo-seed`、`test`、`migrate`、`backup`、`restore-check`
- `docker-compose.yml` + `Dockerfile`：两容器（proxy、app）

验收：

```bash
make migrate && make seed && make smoke       # smoke 内部：迁移→种子→健康→登录→越权→撤销
pytest -q                                     # 全绿
docker compose exec app curl -s localhost:8000/health    # 容器内直连，200
curl -k -s https://localhost/health | grep ok            # 走代理 443，验证对外入口
curl -sI http://localhost/ | head -1                     # 应为 301：80 只做跳转
```

完成定义：空卷启动可复现；`/health` 在容器内与代理两个入口都返回 ok；改密后旧 Cookie 立即失效（同一 Cookie 再请求返回 40101）；跨会员访问他人详情返回 403 且不泄露对象内容；审计表里能看到登录、拒绝与改密三类记录。

匿名申请的令牌（双提交 Cookie）在 S1 只做单元级验证（`pytest -k csrf`），**真实提交烟测放在 S2**——申请页与 `member_application` 表在 S2 才交付。

## 2. 与编码代理的协作方式

1. **先给切片规格，不给整仓提示**：一次只喂本文一个切片 + 相关文档章节。
2. **要求代理自证**：每个切片结束时必须贴出实际执行的命令与输出（`pytest`、`make smoke`），不允许只描述“已完成”。
3. **审 diff 的固定顺序**：迁移 → 模型 → 服务 → 路由 → 模板 → 测试。先看迁移是否与文档一致，再看错误处理。
4. **不通过就退回**：验收命令失败即为未完成，不接受“修一下就好”的口头承诺。
5. **每切片结束打标签**：`git tag slice-S1`，交付周用标签复现每步状态。
